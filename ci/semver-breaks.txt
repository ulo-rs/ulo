# The breaks `scripts/release_check.py` accepts against the last release, which CI's `release check`
# job checks out: `break <package> <lint> <count>  # reason`, `<lint>` as cargo-semver-checks names
# it and `<count>` the distinct items it reports for that lint in that package. A break no entry
# accepts fails the job, as does a count the run does not reproduce and an entry the run does not
# report. The `against` line names the release the entries were written for; when the job's
# baseline is another release the entries are not applied, and the job says so.

against 0.1.0-alpha.3

break ulo-http feature_missing 1  # the `tokio-io` feature is removed, so a build enabling it on the hub cannot put tokio there for every crate beside it; a backend on tokio writes `Upgraded::from_futures(io.compat())` through `tokio-util`'s `compat`
break ulo-http inherent_method_missing 1  # `Upgraded::from_tokio`, the removed feature's constructor; `Upgraded::from_futures(io.compat())` is the same conversion
break ulo-http trait_method_added 1  # `WithHttpStatus::http_status`, the read-back beside `with_http_status`; a type of a user's own implementing the trait adds it
break ulo-handler-codegen constructible_struct_adds_field 1  # `Param::gates`, the parameter's `cfg` attributes every item written for it carries, so a parameter compiled out leaves nothing naming it; a transport macro crate building a `Param` by literal adds the field
