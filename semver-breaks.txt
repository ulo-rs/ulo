# The breaks `scripts/release_check.py` accepts against the last release, which CI's `release check`
# job checks out: `break <package> <lint> <count>  # reason`, `<lint>` as cargo-semver-checks names
# it and `<count>` the distinct items it reports for that lint in that package. A break no entry
# accepts fails the job, as does a count the run does not reproduce and an entry the run does not
# report. The `against` line names the release the entries were written for; when the job's
# baseline is another release the entries are not applied, and the job says so.
