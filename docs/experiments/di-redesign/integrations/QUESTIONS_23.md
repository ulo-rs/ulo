# Questions after the release batch is built and checked (for the designer)

Written for: the designer. The release batch from the salvage rulings (QS-8, QS-9, QS-10, QS-11, QS-14, QS-15's prefix screen) is built, checked by a second model, gated (2,949 tests, no failure) and merged to `master` (#395). Cite these as Q23-P1 onwards. None gates `0.1.0-alpha.2`; each changes a public name or a documented contract, so each wants a ruling before the release makes it stable. Detail: `FRAMEWORK_GAPS.md` F567 to F573.

Paste alongside: core `DESIGN.md` §3.6, §8.3, §10.2; transports `DESIGN.md` §2.2, §3.1, §4.3, §5.2, §6, §7.

## Rulings needed

**Q23-P1. Settings for `OtelModule` and `WsModule` (QS-14, F568).** `Module::settings` now lets a module expose the settings its identity does not cover, so a second registration with other settings is a wiring error. `StoreModule`, `ConfigModule` (`deny_unread`) and the GraphQL engine module expose theirs. `OtelModule` (its exporter options) and `WsModule` (its adapter and defaults) have the same defect but hold no value that can be compared: an exporter and a broadcast adapter are opaque. Options: give each a name or kind to compare; or accept first-reached-wins for those two and document it. Recommendation: a kind name for each, since two different exporters registered under one identity is the case the rule exists for.

**Q23-P2. Screening headers an interceptor writes onto a gRPC reply (QS-15, F567).** The `grpc-` prefix screen covers handler metadata and a pre-dispatch refusal's headers. An interceptor writing `grpc-*` straight onto `Reply.headers_mut()` is not screened. A screen over the finished reply would strip the framework's own `grpc-status`, `grpc-message` and `grpc-status-details-bin` from a trailers-only reply, which carries them as headers. Options: screen only the names an interceptor adds; or exempt trailers-only replies. Warn once per process per dropped name. Recommendation: screen the interceptor's additions only.

**Q23-P3. Where a depth refusal sits (QS-9).** `Json<T>` answers 422 when the JSON is valid but does not fit `T`. serde_json raises some such failures as `Category::Syntax` (`{"abc":"x"}` into a map with numeric keys, `1e400` into `f64`, a lone surrogate into a `String`, nesting past 128). A syntax failure on a body that is valid UTF-8 and parses as JSON at all now counts as a fit failure. Is exceeding the nesting limit content (422) or a resource limit (400)? Recommendation: 422 with the same detail, since the body parsed as JSON in the sense the client meant.

**Q23-P4. A taken empty body on a bodiless request (QS-8).** A guard that takes an empty body on a `GET` turns `Option<Json<T>>` into 500 with a warning, matching QS-8's wording. The slot could record that the taken body was already at end of stream and answer "missing". Keep the ruling's reading, or distinguish an empty taken body? Recommendation: keep the ruling; a guard that takes a body has taken it, and the handler should not guess what it held.

**Q23-P5. GraphQL POST's fit edge (F572).** The `Json` fix does not reach the GraphQL POST: `1e400` inside `variables` answers 400 `Encoding` where the draft's "not a well-formed request" is 422. Patch it in the release? Recommendation: yes, with the same rule as Q23-P3.

## Confirmations

**Q23-P6. The broadcast wire (QS-10).** The codec is the public module `ulo_ws::wire` (`encode`, `decode`, `VERSION`, `Undecodable`). A message is `[0x01]`, the target as compact JSON, `\n`, the frame; node ids are 32 hex digits (a 128-bit number does not survive a JSON reader that holds numbers as doubles); unknown fields are refused. The old unversioned wire starts with `{` and is dropped with the warning, with no compatibility shim; version numbers stop below `0x7B`. A message with another version, the old layout or an unknown audience kind is dropped with a warning once per process per kind, repeats at debug, malformed messages warn every time, the receive loop never ends on a bad message. The kind is cut at 64 bytes and 64 kinds are remembered (not in the ruling), so two kinds alike in their first 64 bytes count as one. `Target` and `Audience` lose their serde derives; nothing in the workspace used them. Confirm the shape, the hex node id, the removed derives and the bound.

**Q23-P7. The queue bounds and the halted contract (QS-11).** The knob is `max_queued_items(Count)` on `RpcClient`, `RpcClientModule` and `Server` (decision 11: a count is `max_*: Count`), default 1,024; `Count::Unlimited` is accepted as the explicit opt-out; `Count::Max(0)` is refused as `ZeroCount`. An overflow ends only that call with `Unavailable` and the reason `overflow`, after sending `cancel`; a call's last frame always fits past the limit. A halted request queue ends the handler's `Inbound` with one final `Err(ExtractError::Overflowed { param, limit })`, a new public variant, then the end; the call's answer is `overflow` whatever the handler does. Ratify the variant, the contract "a halted queue ends failing", and `Unlimited`. The limit counts items, not bytes (F570): at the TCP default `max_frame` a full queue can hold about 4 GiB per call, which the 1 MiB restore under QS-4 reduces to about 1 GiB. A byte bound as well?

**Q23-P8. Module settings (QS-14).** `Module::settings() -> ModuleSettings` returns ordered `(name, Debug text)` pairs compared by text; `Keyed` forwards; `DynamicModule::with_settings` is added; `ModuleDef::import` is `#[track_caller]` so the error names the user's own line. New public types: `WiringError::DifferingSettings`, `ModuleSite`, `DifferingSetting`. `migrate` is compared by the call site of `.migrate(..)`, so two `.migrate(M)` calls written in two places are refused even for the same migrator, while a helper taking the migrator as a parameter has one call site and compares equal for two different migrators. `ModuleSite::Load` records no call site; a `#[track_caller] fn load(..) -> impl Future` that captures the caller before the `async move` records one on stable (verified on 1.88). Setting values print unredacted (a credential belongs in the identity). A self-import that differs reports both `ImportCycle` and `DifferingSettings`. Confirm; record the `Load` call site with the release?

**Q23-P9. The status table (QS-8, QS-9).** New public API: `ExtractError::{Mismatched, BodyTaken, Overflowed}`, `ulo_http::NotAcceptable`, `ulo_graphql::{RequestFault, GqlResponse::request_fault, GqlResponse::fault}`. A missing form field and an unparseable form value are both 422 (every byte sequence parses as urlencoded), so `Option<Form<T>>` is `None` only for an empty body. Query and path failures stay 400 (RFC 9110 §15.5.21 is about content). A GraphQL request error that no engine names renders 422; juniper reports coercion as validation; a client preferring `application/json` but accepting `application/graphql-response+json` gets `application/json` with real statuses; a 406 answers an `Accept` naming neither JSON type; the draft's own `294` is not built. The draft is an unfinished working draft (commit `d027fa2`, 2026-09-28) and every status in it is a SHOULD. Confirm.
