## Gates the merge

**Q20-P1. The README install tag (Q19-P3).** Both first-page READMEs install from the git tag `v0.1.0-alpha.1`, which is 186 commits behind HEAD. At that tag `ulo-db`, `ulo-health-http`, `ulo-health-grpc`, `ulo-otel` and `ulo-otel-otlp` do not exist, `ulo_http` does not re-export `Valid` and `Validate`, and there is no `examples/` directory. The READMEs make no crates.io claim. Options: cut a new tag at the merge and keep the Install section, or point Install at a branch or a revision. Recommendation: a new tag at the merge; until then the Install section is wrong for anyone who follows it.

**Q20-P2. The ALPN list drops further protocols (Q19-P13).** Built as ruled: the list a server offers is exactly what its transport speaks, in the transport's order (`h2` for gRPC, `http/1.1` for WebSocket, both for HTTP). A shared configuration that also names `acme-tls/1` or `h3` loses them; a client offering only a dropped protocol gets a TLS alert. The consequence: a listener that relies on `acme-tls/1` for TLS-ALPN-01 challenges on the same configuration no longer serves them. Confirm that is intended. No gRPC TLS test file exists; the gRPC alert is pinned at the `ulo-net` handshake level.

**Q20-P3. The shape check refuses one direction (Q19-P17).** Built: `Reply::Many` from a handler declared `Unary` or `ClientStreaming` is refused at the reply (the stream is dropped unwritten, the caller gets `Internal` with the reason `shape_mismatch`, the server logs one `warn` naming pattern, handler and declared shape). Not built: a handler declared streaming that replies with one payload. The check runs on the final outcome and cannot tell a handler's reply from one an interceptor or error handler substituted, and `stream_end::a_stream_an_interceptor_discards_reports_nothing` is a valid case of the latter. Accept the narrowing, or carry where the reply came from so the reverse can be refused? Recommendation: accept; the reverse is a wire-valid answer and the cost is a provenance flag on every reply.

**Q20-P4. The RabbitMQ client leaks one thread and socket per call against a silent broker (Q19-P2).** With the defaults the client's 5 s call timeout runs over the 30 s `connect_within`, so a call against a broker that accepts TCP and never answers ends `Timeout` at 5 s, drops its connect, and leaves lapin's `lapin-io-loop` thread and socket; the next call connects again. The server side is bounded and named (`ConnectTimedOut`, `Bind`). The client reaches `ConnectTimedOut` only when the call timeout exceeds the bound. Documented in transports §5.2 and §5.3. Stopping it in code needs a connect the client owns and later calls join. Recommendation: document for the merge, build with F505.

**Q20-P5. Where `ConnectTimedOut` lives (Q19-P2).** It is in `ulo-rpc-rabbitmq`, so `ulo_rpc::connect_error` cannot recognise it and the client's `Unavailable` carries no `connect_timed_out` reason (the message names the bound and the address). Move the type to `ulo_rpc` (F505's uniform `connect_within` would reuse it), re-export it from the rabbitmq crate, and add the arm? Recommendation: yes, with F505, not before the merge.

## Rulings needed

**Q20-P6. `connect_within` takes a `Duration`, not a `Bound` (Q19-P2).** The ruling wrote `connect_within(Bound)`. `ulo-db` and `ulo-ws-redis`, the crates it named, take a `Duration` and refuse zero; Q19-P12 says the name means the same on every crate that has it; `Bound` would add `Unbounded`, which is the hang. Built as `Duration`, zero refused in `usable`. Confirm.

**Q20-P7. A macro handler cannot declare a stream shape while returning `Reply` (Q19-P17).** The conformance fixture `unencodable_stream` returned `Reply::Many` from a `#[message]` handler, which the macro declares `Unary`, and the new check refused it. It is now a typed stream whose second item fails to serialize, which tests the codec refusing an item rather than the link's frame encoding refusing one; a hand-mounted `ServerStreaming` handler answering raw bytes covers the frame case. Is there a case for a shape knob on `#[message]`? Recommendation: no, until an application needs a `Reply`-returning streaming handler.

**Q20-P8. `is_panic` and the new serve end (Q19-P9).** A panicking serve future is `ServeEnd::Panicked(Redacted)`, not `Errored`, so the shutdown outcome keeps panic and error apart (`ServeEnd` is `#[non_exhaustive]`). `is_panic` does not recognise it. Should it answer true for a panicked serve end?

**Q20-P9. The separator in a link failure (Q19-P8).** The ruling wrote "transport `Rpc`, link `nats`: <text>". Built: ``transport `Rpc`: link `nats`: <text>``, because the `transport `X`: ` prefix comes from core (`error/configure.rs:108`). The link is also a structured field (`PrepareEntry::subject()`). Accept the colon?

**Q20-P10. The truncated report's header counts the notice (Q19-P11).** At the pass cap the report lists 2,048 problems and the notice "stopped after 2048", and the header above them reads "(2049 problems)". Count only real problems in the header, or leave it? Recommendation: count only real problems.

## For the record

**Q20-P11. Two premises in Q19-P2 point 4 did not hold, measured.** NATS's first connect has no bound against a server that accepts and stays silent: async-nats 0.46.0 bounds only the TCP connect (`connector.rs:430`), the `INFO` read after it (`:476`) has none; both server and client were still waiting at 45 s. Redis is bounded at about 16 s, not 1 s: `ConnectionManager::new` connects at once with 1 s per attempt and six retries on a backoff from 100 ms. MQTT failed at 5.0 s and RabbitMQ is now 30 s; Kafka is read from the source, not probed. Transports §5.3 holds the table with source lines. F508 files NATS; F505's uniform `connect_within` should cover it.

**Q20-P12. What the RabbitMQ bound covers (Q19-P2).** One `ulo::timeout` on the app's `Timer` runs over the whole `listen` sequence: plain connect, close, recovering connect, and the queue and consumer declarations (otherwise a broker that goes silent after the handshake holds `listen` one step later). A server that listens without `prepare` times the wait on the link's own runtime, because the gated tests call `listen` directly. After the bound fires, the thread retrying the serving connection keeps going and panics once the link's runtime shuts down (tokio `time/entry.rs` 539); it ends that thread only. Documented in §5.2.

**Q20-P13. `Ext<A>` declared no longer covers `Ext<B>` (Q19-P14).** `ReadKind::Extension` holds a `TypeId`; `UndeclaredRead::extension()` is new and `key()` is `None` for an extension. No injection point in the tree declared one `Ext` type and read another. The unlocated 25 ns stays F507.

**Q20-P14. gRPC hand-written handler choices (Q19-P4).** A spec with no route is refused (it would report `None` while the server serves the marker's path); a shape-less spec for a streaming marker is refused (the spec's default shape is `Unary`); a spec with a route and no shape is accepted for a unary marker; the macro's call is boxed twice, once as RPC and once as WS. `public_reach.py` exits 0 over 20 crates.

**Q20-P15. How `into <metadata>` and the derives are checked (Q19-P5 and the listed items).** The refusal is an autoref probe on the `Meta` trait that `#[module]` emits before every `into K: [..]` list, covering `PreDispatch<T>` (HTTP, gRPC, WS), `Upgrades` and user `Meta` types; `HubMeta` is `pub(crate)` and cannot be named. `contribute` stays open to a metadata key when called by hand. The derives resolve their path through `proc-macro-crate` over `ulo-transport`, `ulo-rpc`, `ulo-http`, `ulo-ws` and `ulo-grpc`, preferring a candidate under `[dependencies]` over one under `[dev-dependencies]` (the checker found the first-found rule picked a dev-dependency and failed the build). Nothing pins the `ulo-ws`, `ulo-rpc` or `ulo-grpc` re-exports (F510).

**Q20-P16. Config report accessors (Q19-P11).** `Problem::truncated()` is new public surface; the extra loop pass only learns whether anything is left; skipped sections are a sorted set, which took the sections suite from 9.8 s to 0.9 s. The 9.6 s figure for 3,000 entries is the checker's, not re-measured.

**Q20-P17. The example list lives in one place (Q19-P3).** The root README's example table is the only list; `scripts/check_examples.py` now fails on a missing, extra or out-of-order row, so a new example needs a row and cannot drift. Nothing is left to rule; listed so the table is not mistaken for derived output.
